## 2. 怎样理解学生的这次失败

学生先查应用说明、Spotify API 列表和具体 API 文档，再搜索 artist。第 5 个动作（0-based step 4）在取得有效认证前调用 follow_artist，官方公开 API 返回 401。随后学生读取模拟账户信息、读取公开 profile 并登录；第 8 个动作后预算结束，尚未执行后续受保护操作，也没有提交完成标志。

这条轨迹中的 7 个动作没有执行异常，1 个动作收到公开认证错误。它说明当前模型、执行端、公开 API、回传和官方评分确实连通；暴露了一个认证顺序/恢复成本案例。**它既不能证明长程状态漂移，也不能证明 RSI 有效或无效。**只有一个 train 任务，且预算和 thinking 设置是工程 profile。

| 成本或资源 | 实测 |

当前生成明确在 tokenizer EOS 或模型 EOS 停止；先按 ID 去除末尾控制 token，再解码，严格代码块解析规则没有放宽。raw_text 留在私有模型诊断，不能直接作为 accepted 训练轨迹。

API 代理内部路由参数使用 positional-only，避免与官方端点的 app_name/api_name 关键字重名。执行端保留变量，自动回显最后一个非 None 表达式，接近交互式 Python 的使用方式；生成代码仍全部在 Bubblewrap 内运行。没有增加网络或文件写权限。

下载收尾还修复了 Windows 锁文件句柄未关闭便删除的问题；独立重验本地全部资产通过。上传曾发生连接重置，使用 SFTP 续传，服务器完整哈希随后通过。错误轮次没有删除或记为成功。

## 5. 怎样重跑

每次先查看当前空闲 GPU，复制其 UUID；这里不把一次空闲状态当作后续预约。另用新的 run ID，不能覆盖已有目录。

```bash
ssh -p 22 lyf@211.81.55.158
nvidia-smi --query-gpu=index,uuid,memory.free,utilization.gpu --format=csv
source /nfs-data/sdf/lyf/rsi-long-horizon/scripts/activate_appworld_rootless.sh
cd /nfs-data/sdf/lyf/rsi-long-horizon/code/RSI-Towards-LongHorizon
python scripts/server/run_student_episode.py \
  --run-id student-p0-$(date -u +%Y%m%d-%H%M%S) \
  --gpu-uuid GPU-替换为刚确认空闲的实际UUID \
  --profile engineering-smoke
```

上述是工程 profile：non-thinking、greedy、每次最多 1024 tokens、8 动作。正式 B0/B1 候选是 thinking、固定采样与 seed、8192 tokens、64 动作，仍需单独做协议/预算 smoke 并冻结。两类运行不能混合计算成功率。
