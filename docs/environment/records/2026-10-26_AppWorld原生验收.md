## 这次验证了什么

可以把这次工作理解为：先确认“考场和判卷程序能用”，还没有让学生模型参加考试。安装、数据、公开 API 和官方评分已经真实运行，不再只依赖 toy demo。

| 同一个任务的三种运行 | 官方评分通过项 | 任务是否成功 | 解释 |
|---|---:|---|---|
| 初始化后只读公开 profile，不做任务 | 1/5 | 否 | 评分器没有把空操作误判成成功 |
| 读取公开 profile，再执行官方正确解 | 5/5 | 是 | 环境可执行任务，官方评分器能识别正确结果 |
| 正确解运行后重新初始化，再只读 profile | 1/5 | 否 | 上一轮完成状态没有直接带到这一轮 |

三组均实际执行 5 项官方检查。空操作的“1/5”不是任务成功率 20%；该任务要求全部检查通过，官方 `success` 为 false。

另外六项验收检查均通过：公开 API 可读、初始负例不成功、正确解成功、重置后负例不成功、三次初始公开 profile 哈希一致、所有已展开原始数据文件哈希不变。

重置证据覆盖公开 profile 和上述评分行为，**没有证明全部数据库状态逐项等价**。本轮没有检查学生代码的隔离、越权读取或评分器攻击。

## 怎样只重跑验收

环境和数据已经安装，不要再次完整执行 bootstrap。以下命令只重跑可信官方代码，生成新的三组独立结果：

```bash
source /nfs-data/sdf/lyf/rsi-long-horizon/scripts/activate_appworld_native.sh
cd /nfs-data/sdf/lyf/rsi-long-horizon/code/RSI-Towards-LongHorizon
export RSI_NATIVE_RUN_ID=native-p0-$(date -u +%Y%m%d-%H%M%S)
bash scripts/server/run_appworld_native.sh
```

报告写入项目根目录的 `reports/$RSI_NATIVE_RUN_ID.acceptance.json` 和 `.status.json`。运行编号必须全新，脚本拒绝覆盖旧结果。首次离线安装入口保留为 `bootstrap_appworld_native.sh`，它要求已校验的 wheelhouse 和数据包，且拒绝覆盖已有数据目录。

## 首轮失败与修复

首轮编号 `native-p0-20261026-120539` 完成了安装和数据准备，但验收脚本错误地调用 `world.evaluate(suppress_errors=False)`。预期失败的空操作触发官方评分断言，流程因此提前退出。

核对官方接口后改为 `suppress_errors=True`：由官方 TestTracker 记录失败项并返回完整统计；仍然要求正确解通过，且不允许零项测试算成功。新增回归测试验证负例分数不会丢失。首轮 status 和服务器原始日志保留，没有把失败记录覆盖成成功。

修复后只重跑验收阶段，没有重复安装或解包数据。本地和服务器均通过 23 项项目测试。
