## 当前研究问题

在固定部署 Harness `h0` 和相同学生起点下，由固定 Harness/审查器 `K0` 产生的、经过执行前审查的长程交互轨迹，能否通过 SFT 内化为学生行为，使其在**移除审查器和私有 K 后**，对未见任务获得比普通自训练更好的成功率或长程状态保持能力？

这是一条待验证的问题，不是已确认的创新主张。Harness-Zero 已展示审查轨迹到 SFT 的主要工程链；因此本项目必须进一步指出一个具体长程失效机制，并证明 K 引导的数据相对公平对照具有增量。

## 候选机制与范围

当前优先调查的候选失效机制是长交互中状态/约束漂移：学生在早期观察到的前置条件、已完成子目标或资源约束，到了后续操作时未能持续遵守。此机制还没有从真实 benchmark 轨迹中确认。P1 应先抽查代表性失败，区分状态遗忘、工具协议错误、目标偏移、未发现错误、恢复失败和环境故障，再决定是否保留该机制。

“能力内化”限定为：在学生继续拥有相同公开工具、文件系统和 `h0` 的情况下，权重学会更可靠的状态维护、检查或恢复。移除的是私有审查器/K，不是环境本身提供的合法观察与工具。

## 可证伪假设

- **H1，外部指导可执行：** 对训练/开发任务，`M0 + h0 + K0` 的审查干预会让可核查的 accepted action 相比裸学生更符合当前公开状态和动作约束；记录审查覆盖、替换位置、动作合法性、最终 verifier 结果与调用成本。
- **H2，指导数据可内化：** 在相同学生起点、部署 `h0`、数据预算和训练配方下，B3 的 reviewer-free 结果优于 B2，尤其在预先定义的长依赖档，并在未见 task family/scenario 上保留收益。
- **H3，收益不是教师或数据量的替身：** 当有效训练 token、任务覆盖和训练更新可比时，B3 仍优于 B2；后续若要归因给 Harness/K，应增加“相同教师但不使用 K”的审查数据对照。

H1 不成立时暂停 SFT；H1 成立而 H2 不成立时，不宣称能力内化，先排查轨迹可学习性、模板/loss mask、长度截断和 checkpoint 重载；B3 只在训练集或有 reviewer 时提高，不支持 reviewer-free 泛化主张。

## 首轮条件

| 条件 | 定义 | 要回答的问题 |
|---|---|---|
| B0 | 初始学生 `M0 + h0`，无 reviewer | 裸模型基线与失败分布 |
| B1 | 同一学生 `M0 + h0 + K0/reviewer`，只评测、不训练 | 外部指导本身是否有效；不是学生上界 |
| B2 | B0 可验证的学生轨迹做 SFT，再用 `h0` 评测 | 普通自训练收益 |
| B3 | K0 审查后 accepted 轨迹做 SFT，评测只用 `h0` | 核心内化条件 |
| B4（归因阶段） | 固定教师执行通用审查但不给 K，数据量与 B3 对齐 | 区分 Harness/K 信息与教师的一般能力 |

首轮按 B0/B1 推进；只有真实指导信号和数据审计通过后，再进入 B2/B3。B4 在数据和预算允许时用于更强归因，不作为当前工程阻塞的理由。

## 变量、指标与控制

- 主要自变量：训练数据来源（无训练、普通自训练、K 审查轨迹；后续可加无 K 教师审查）。
- 主要因变量：reviewer-free task success，按预先定义的依赖深度档分别报告。
- 过程指标：合法动作率、约束/前置条件违例、任务恢复率（只在能可靠标注错误事件时使用）、步骤/模型调用数、审查/替换数和 token 成本。
- 控制：学生 checkpoint/tokenizer、`h0`、任务 split、prompt/chat template、采样参数、训练 token/更新预算、最大步骤、重试规则和 verifier 版本。
- 分析单位：独立 task family/scenario；对同一任务配对比较，按 scenario 聚类汇总，避免把同族实例当独立 RSI 重复。

## 下一决策门

P0 先完成真实环境的一任务闭环；P1 在训练/开发 split 抽取约 20–50 个代表性任务或可获得轨迹做失败归因和 B0/B1 诊断。该规模只用于可行性、错误类型与成本估计，不用于显著性结论。最终 test 在协议冻结前不用于选择 K、checkpoint 或超参数。
