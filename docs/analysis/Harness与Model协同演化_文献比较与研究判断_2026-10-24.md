# Harness 与 Model 协同演化：文献比较与研究判断

日期：2026-10-24（Asia/Shanghai）

用途：在等待服务器期间，理解近邻工作、澄清当前 IDEA 的可检验问题，并决定先做哪些探索实验。本报告是研究建议，不是已成立的创新声明，也不替代研究者自己的判断。

## 1. 结论先行

1. Harness 与模型交替更新已经有直接近邻；“接成闭环”本身不足以支撑新颖性或狭义 RSI。
2. 当前 IDEA 值得作为探索性原型验证。先检验“外部指导有效 → 数据可学习 → 移除指导后仍有增益”，再检查更新 Harness 和元代理是否必要。
3. Motivation 应当现在有一个可被推翻的暂定版本，在探索中修订，在确认实验前固定关键假设与评测协议；论文写作阶段再整理表达。
4. 一个适合组织实验的问题是：“最能帮助当前学生完成任务的 Harness，是否也最能训练出下一代独立学生？”这与 OPC 的可学习性问题、HELIX 的执行/数据两种前沿已有交集，不能直接当成我们的独创贡献。

## 2. 范围、来源与勘误

本文选取截至上述日期与本 IDEA 直接相关的四篇主比较论文，另以 HELIX、Harness-Zero 和 Hyperagents 校准证据边界。不是穷尽检索，也不是完整查新。

引用依据为 arXiv 官方摘要及 HTML 正文的指定版本；数值均为作者报告，本项目尚未复现。不同论文的环境、模型、指标和预算不同，不能横向用分数给方法排总榜。文中“百分点”均指绝对差值。

**勘误：** 前一版项目分析将 SIA 的题名与 arXiv:2609.04912 错配。该编号对应 TreeFI，与 SIA 无关，旧引用撤回。正确论文是 SIA: Self Improving AI with Harness & Weight Updates，arXiv:2605.27276。Co-Harness 的准确题名也已同步校正。此前的摘要级核对不能视为完成全文验证。

## 3. 我们究竟打算验证什么

依据 Seminar_01/Note.md §3.1，保留以下对象区别：

- M_t：学生模型；部署时使用固定、极简的 h0。
- A_t：产生或改进 Harness 的元代理；其规则、程序或学习资产可能被继承。
- K_t：训练期私有的长程 Harness。审查者借助它，在动作执行前 PASS 或 REPLACE；替换动作必须可以在 h0 下执行。
- D_t：由实际接受并执行的动作组成的公开轨迹；用于训练 M_(t+1)。

设想的回路是 A_t → K_t → 学生诱导状态上的审查与轨迹 → M_(t+1)，再用新的模型/经验改进 A、K。最终目标是撤去训练期私有 K 和审查者，在同一个 h0 下保留可迁移的收益。

上述箭头目前是方法假设。已有 toy 原型、训练格式导出或流程图，都不能证明真实长程能力已内化，更不能证明改进器本身变强。课程自动延长也暂不作为第一阶段必需部件。

## 4. 四篇直接近邻

### 4.1 Co-Harness：随模型变化修复 Harness

**来源：** [P1]，2026-07-17，本文核对 v1 的方法及 Table 6。

- **Motivation：** 静态 Harness 与变化后的模型可能不匹配；Harness 也决定后续训练数据的质量。
- **Methodology：** HarnessCritic 分析当前模型的失败，局部修改提示、工具、技能、记忆等；经非回退检查后收集轨迹、SFT 更新模型，再继续优化 Harness。
- **Result：** Qwen3-8B/32B 在 AIME24/AIME25/HMMT25 的六组组合平均准确率，R0/R1/R2 为 58.5/73.5/78.9%。R0 已含演化后的 Harness；20.4 个百分点不是相对裸模型的收益。
- **与我们相比：** 它已非常接近“Harness → 数据 → 权重 → 下一轮 Harness”。论文也讨论内化及 without-Harness，不能仅凭“最终简化部署”宣称区别；需核对严格固定 h0、私有信息与审查数据边界。

### 4.2 SIA：决定何时改 Harness、何时改权重

**来源：** [P2]，2026-05-26，本文核对 v2，尤其 Table 3 与 §9。

- **Motivation：** 只优化 Harness 或只训练权重都有局限，两种手段可互补。
- **Methodology：** Meta-Agent 初始化系统；Feedback-Agent 根据执行反馈选择修改 Harness 或更新模型权重。报告使用 gpt-oss-120b、外部元/反馈模型与 LoRA。
- **Result：** LawBench 任务生成的分类脚本/流水线准确率为初始 13.5%、Harness-only 50.0%、Harness+weight 70.1%；这不是裸 LLM 法律问答成绩。
- **与我们相比：** 重点是选择优化手段，而非私有 K 的执行前审查与固定 h0 内化。§9 明确反馈代理仍是冻结的 LLM，把学习反馈决策列为未来工作，不能据此声称“改进器已自我提升”。

**评测借鉴边界：** 正文描述使用 test split 执行生成脚本取得 rollout reward。制定自己的评测时必须区分优化反馈集与最终独立测试集，不能直接照搬并解释为未见任务泛化。

### 4.3 On-Policy Correction：学生状态上的修复比整轨迹模仿更可学

**来源：** [P3]，2026-09-08，本文核对 v1 的方法与 Table 1。下文简称 OPC，仅为行文方便。

- **Motivation：** 弱模型模仿强模型完整成功轨迹，可能学不到可执行的规划，甚至退步。
- **Methodology：** 先优化 h*，在学生自己到达的状态上，让专家修复可恢复的单轮错误，尽量保留其余轨迹，再进行 LoRA SFT；不能额外假定只对修复 token 计算 loss。
- **Result：** 七个企业任务平均分：原模型+h0 为 29.2%，原模型+h* 为 78.0%，整轨迹模仿+h* 为 63.1%，纠正训练+h* 为 79.7%。纠正优于整轨迹模仿，但相对已有 h* 仅提高 1.7 个百分点。
- **与我们相比：** 与“学生诱导状态上的干预数据”最接近；最佳结果保留 h*。实验证据主要是一轮顺序优化，不能当作多轮模型—Harness 回返已经成立。

### 4.4 VACE：用当前模型验证 Harness，防止交替更新回退

**来源：** [P4]，2026-09-29，本文核对 v1 的 Table 2 与 §4.4。

- **Motivation：** 对旧模型有效的 Harness 补丁可能伤害新模型，盲目交替更新不保证进步。
- **Methodology：** 交替进行 agentic RL 与真实 Harness 编辑；在更新后的 checkpoint、相同验证任务上比较候选和现有 Harness，仅接受更优候选，否则回滚。
- **Result：** Qwen3.5-9B：OfficeQA 准确率 RL-only 38.83、WHALE-style 40.67、VACE 45.26；AutomationBench 平均部分得分为 66.10/68.25/75.19，不能叫成功率。44 个候选中 17 个有害补丁被拒绝。
- **与我们相比：** 强调模型—Harness 配对和选择稳定性，评测选出的配对；不直接等于撤去训练期 K 后的学生收益。WHALE-style 是作者重建的比较基线。

## 5. 三篇校准材料

### 5.1 HELIX：完整提案不等于完整实证

[P5] HELIX: Model–Harness Co-evolution for Recursive Self-Improvement，2026-08-14，v1。提出可追溯的 Harness 组件组合、同题 sibling 轨迹和 build–update–rebuild 框架。

但报告实验实际冻结模型；100 个 LiveCodeBench-derived 修复任务中，基线 50/100、最佳固定候选 52/100。79/100 是多个候选事后成功并集，不能当作一个可部署代理的成绩。主集合使用公开测试，不等于官方隐藏测试表现。没有真正训练并重建下一轮模型—Harness。

其 §7.2 已区分执行前沿与数据前沿：最佳部署 Harness 未必提供最佳学习数据。这个方向值得借鉴，但不能直接据为本项目的新概念。

### 5.2 Harness-Zero：已存在“撤去私有 Harness”的路径

[P6] Harness-Zero: Harness Distillation，本文核对 v1。私有参考 Harness 通过执行前 PASS/REPLACE 指导学生，接受的轨迹用于 SFT，部署时移除参考支持。这是我们最直接的方法来源；单向蒸馏有效并不自动证明重复回返或改进器收益。

严格讨论“自我”时，要说明系统边界：固定的外部强教师参与时，可以先称系统改进或蒸馏；不能仅因为学生升级就把所有改进能力归给学生自身。

### 5.3 Hyperagents：更接近对“改进能力”的直接检查

[P7] Hyperagents，本文核对 v1，尤其 §5.2。冻结基础模型，允许任务代理与元代理程序共同演化；额外考察演化系统在新领域继续产生改进的表现。

跨域迁移的是整个 hyperagent，包含 task 与 meta agent，并非只替换元代理的纯控制实验。因此其迁移后的改进收益，比仅展示任务成绩曲线更接近狭义 RSI 证据，但还不能声称完全隔离了元改进机制的因果贡献。

## 6. 三类 RSI 应怎样判定

沿用 Note.md §2.1 的操作性口径，而非声称全领域已有统一定义：

- **广义自我改进：** 系统利用自身输出或经验改善后续表现。外部教师的归属需要明确。
- **结构性 RSI：** 存在对自身或继承工件的回返路径；要标明是 Harness 层回返，还是实际完成模型—Harness 多轮回返。
- **实证/狭义 RSI：** 证明继承后的改进机制更有效地制造下一次改进。

三者是递进条件，不是互斥标签。可编辑元代理、轮次增加或分数上涨，均不能单独满足第三条。

| 工作 | 广义自我改进 | 结构性回返：实际做了什么 | 狭义 RSI 的证据判断 |
| --- | --- | --- | --- |
| Co-Harness | 是 | Harness 与权重实际多轮交替 | 未隔离“改进器更会改进”的收益 |
| SIA | 是，以整个系统为边界 | Harness/权重更新回到后续执行与优化 | 未确证；反馈代理冻结 |
| OPC | 是 | Harness 搜索有回返；完整模型—Harness 多轮回返主要为后续方向 | 未确证 |
| VACE | 是 | 实际交替更新，并用当前 checkpoint 筛选 Harness | 未隔离改进器收益 |
| HELIX | Harness 层有经验驱动改进 | Harness 候选搜索有回返；完整 build–update–rebuild 未执行 | 未确证 |
| Harness-Zero | 蒸馏/系统改进成立；“自我”需说明教师边界 | 已验证单向内化，递归回返不能由此推出 | 未确证 |
| Hyperagents | 是 | 任务与元代理的继承性代码共同演化 | 有针对性的跨域后续改进证据，但任务/元代理迁移未完全分离 |
| 我们当前 IDEA | 尚待真实实验 | 设计中有完整回路，工程与科学证据尚未完成 | 不能预先宣称 |

对我们来说，较有说服力的后期实验是：固定初始学生 M、任务、初始 K、反馈权限和总预算，仅把旧改进器 A0 换成演化后的 At；比较它们制造出的后继学生质量或单位预算收益，再检查跨任务保留。不能拿“更强学生 + 新 A”对比“更弱学生 + 旧 A”，就归因于 A 的提升。

## 7. “拼接”IDEA 如何转化为研究问题

从两个已有方法的连接产生假设，是正常的研究起点。是否有价值，取决于能否发现并解释一个现有工作没有充分解决的问题，以及提供可信证据，不取决于最初是不是“拼接”。

目前要区分三个目标：

1. K 的即时辅助收益：它能否让当前 M 多做对任务？
2. K 的教学价值：它生成的数据，能否让下一代 M 在 h0 下独立泛化？
3. A 的元改进收益：演化后的 A 能否更高效地产生有教学价值的 K？

这三个目标可能相关，也可能冲突。强教师大量接管可能得到高辅助分，但产生学生难以学习的轨迹。这只是合理风险，不是我们已经观察到的事实。

一种候选研究问题是：当两个 K 的辅助得分接近、训练数据预算相同时，学生可见的修复依据、干预位置或指导密度不同，是否导致不同的独立学习收益？先做小比较，才能决定是否值得引入以“下一代学生收益”为目标的外层搜索。

即使出现正结果，也需要对照 OPC、Co-Harness、HELIX 的具体设定继续查新。“固定 h0”“长程任务”“多一层元代理”都不是自动成立的创新点。状态/约束漂移、错误恢复等仅是候选失败机制，等待真实轨迹确认。

## 8. Motivation 应该什么时候确定

建议采用“现在提出暂定动机 → 探索中修订 → 确认实验前冻结 → 写作时清晰表达”的顺序。

### 8.1 现在：写三句话即可

1. **问题：** 在什么条件下，哪个可观察行为存在不足？
2. **缺口：** 为什么现有做法可能没有解决它？哪些只是猜测？
3. **假设：** 我们的干预为什么可能有效？什么结果会让我们承认这个解释不成立？

当前可采用的暂定版本是：

> 研究目标是让长程任务中的外部支持转化为模型在固定 h0 下可复用的独立能力。我们猜测，不同 Harness 的即时辅助效果与教学价值可能并不一致，因此先检验审查轨迹能否被学生吸收，再检验随学生变化更新 K 是否比固定 K 更有效。具体失败机制由真实轨迹决定。

这是一份工作假说，尚不是被文献或实验确证的普遍缺口。现在不必先写出最终 Introduction，也不必在看到真实失败前选定“状态漂移”作为唯一解释。

### 8.2 探索中：允许发现真正的问题

如果真实失败主要是工具格式，应先修工具接口；如果辅助成绩高但训练后无收益，应研究数据可学习性或教师接管；如果固定 K 与更新 K 等效，就承认当前证据不支持增加演化层。允许研究方向被证据修正。

先优化系统也可以服务于探索，但不能把成功后想到的解释包装成事前预测。事后发现的新规律应标注 exploratory，再用预留任务或独立数据验证。

### 8.3 确认实验前：固定能影响结论的选择

固定主假设、主要终点、对照、任务划分、数据可见性、预算与停止规则。训练/优化只看训练与开发反馈；最终测试不能反复用于选择 K、挑 checkpoint 或改动动机。

论文本身的叙述可在写作时重组，但支撑叙述的数据来源和探索/确认边界必须真实。

## 9. 是否先做粗糙版本：赞成，但先拆依赖

赞成做一个有边界的探索 pilot。目标先是知道“哪条箭头有效、哪条断了”，而不是立即证明完整 RSI。推荐顺序如下。

| 阶段 | 最小问题与对照 | 得到什么才继续 | 如果失败意味着什么 |
| --- | --- | --- | --- |
| P0：真实执行 | 小批真实任务，M+h0，无 K；验证环境、动作历史、评分与可重放记录 | 能逐步解释成功/失败，排除接口与环境故障 | 先修工程，不把基础故障解释为长程推理缺陷 |
| P1：固定 K | 同一 M：无 K vs 固定 K 审查；记录替换、恢复、成本与公开依据 | 辅助收益存在，替换合法且有公开依据 | K/教师/目标失败机制可能选错，先不要训练大闭环 |
| P2：单轮内化 | 同起始 M、同训练算法：不训练 vs 自训练 vs K 审查数据；可加同教师无专门 K | 撤去 reviewer/K、固定 h0、未见任务上仍有收益 | 外部帮助不等于可学习；检查数据、接管比例与训练实现 |
| P3：更新 K | 相同模型更新轮数与总预算：固定 K vs 随 M 更新 K | 更新 K 产生额外、可保留收益 | 简单固定 K 可能已足够，不强行增加元层 |
| P4：元改进 | 同 M/任务/预算下交换旧 A 与新 A，并跨任务检查 | 新 A 更有效地产生后继改进 | 任务代理进步不等于元改进；调整狭义 RSI 主张 |

P2 中自训练与 K 组应报告生成预算、有效训练 token、训练算力和成功数据量；若这些不能同时匹配，预先声明主比较匹配什么，并记录其余差异。不能通过无限补采样隐藏教师成本，也不能把测试样本混入成功数据筛选。

第一轮不同时演化 M、K、A 和课程。后续是否加元层，由 P2/P3 的证据决定；即使最终保留简单方法，只要问题、解释和验证扎实，也有研究价值，但不保证达到特定会议录用标准。

## 10. 服务器申请期间可以推进的事情

1. **研究者先作一个判断：** 目前最想检验的是“可内化”“更新 K 有用”还是“改进器本身变强”？建议以可内化作为第一项，但保留个人判断。
2. **读近邻的关键段落：** Co-Harness Table 6、OPC Table 1、VACE Table 2、SIA §9。分别回答它们训练什么、部署保留什么、哪条回路实际跑过。
3. **做小规模轨迹审查：** 优先使用现有公开日志/参考案例，标明首次偏离、可见依据、可能修复与替代解释；缺失材料时只建表，不编造案例或数据。
4. **先写一页 pilot 协议：** 明确 h0、K 的可见信息和编辑范围、教师边界、任务划分、成本记录、单轮评测与有限预算。数值待服务器配置确定后填写。
5. **工程只补必要缺口：** 准备真实执行日志、接受动作历史、数据来源与训练/开发/测试隔离的合同；不要仅因为暂时没有 GPU 就继续扩建复杂框架。

这一阶段最有价值的产出是“一个可以被实验否定的小问题和一份能解释结果的协议”，不是更多闭环箭头。
