## 1. 先建立一个简单的整体认识

你现在面对的不是“一台服务器”，而是同一个 IP 地址后面的几个入口：

    你的电脑
      │
      ├── SSH 22  ──> A100 计算服务器：运行模型和实验
      │
      └── SSH 9902 ─> 数据站：存放数据集、模型和大文件

9901 也是一台 A100 服务器，但管理员说近期不要使用，所以不连接。

最简单的分工是：

- **A100 服务器**：负责“算”，例如运行 Agent、模型推理、训练；
- **数据站**：负责“存”，例如保存模型、数据集、checkpoint 和大日志；
- **你的电脑**：负责编辑代码、查看结果、通过 SSH 操作远程机器。

数据站上的文件能不能直接被 A100 服务器读取，要看管理员是否配置了共享目录；没有配置时，就使用 scp 或 rsync 传输。

## 3. 管理员负责什么，你负责什么

### 3.1 需要管理员确认或完成的事情

这些事情涉及整台机器、共享资源或其他用户，你不要自行决定：

| 事项 | 为什么需要管理员 |
|---|---|
| 指定你可以使用的目录 | 目录可能属于其他项目，且需要设置权限和配额 |
| 指定数据站的目录 | 数据站有多个存储盘，容量和用途不同 |
| 告诉你使用哪种调度器 | 可能是 Slurm、PBS、Kubernetes 或实验室自定义系统 |
| 分配 GPU 队列、账户和并发额度 | 直接占卡可能影响其他项目 |
| 确认 Docker/Apptainer 是否可用 | 容器权限通常由管理员控制 |
| 提供或安装 CUDA、PyTorch、Python 等公共环境 | 系统级软件不能随意修改 |
| 确认模型下载、外网和镜像仓库规则 | 模型可能很大，也可能受网络和许可限制 |
| 提供 SSH 主机指纹 | 用于确认连接的确实是正确服务器 |
| 清理接近满载的共享盘 | 删除文件可能影响其他用户 |

### 3.2 你可以自己完成的事情

在管理员给出目录和规则之后，以下事情通常由你负责：

- 使用 SSH 登录 22 或 9902；
- 在管理员分配的项目目录中创建自己的子目录；
- clone 项目 Git 仓库、切换分支和提交代码；
- 在允许的位置创建 Python 虚拟环境；
- 安装项目依赖，并保存依赖版本；
- 编写实验配置和作业脚本；
- 提交自己的作业、查看自己的日志和停止自己的作业；
- 保存实验配置、Git commit、模型版本、任务清单和结果摘要；
- 把结果同步回本地电脑。

你现在可以做的准备工作包括：整理代码、准备实验配置、向管理员询问目录和调度器、学习基本 SSH 命令。暂时不要在未知目录下载模型或安装环境。

## 4. “非 /home 项目目录”到底是什么意思

/home/lyf 是你的个人家目录。Linux 用户登录后通常会进入这里。管理员说“尽量不要在 /home 下放数据、模型、环境”，意思是：不要把几十 GB 的模型、数据集、Docker 文件或 Python 环境放在这个个人小目录里。

非 /home 目录就是管理员为项目分配的其他路径，例如：

    /data/lyf/rsi-long-horizon
    /scratch/lyf/rsi-long-horizon
    /project/lyf/rsi-long-horizon
    /nfs-data/sdk/lyf/rsi-long-horizon

这些只是例子，不能直接使用。你当然可以使用非 /home 目录，但前提是：

1. 管理员明确告诉你具体路径；
2. 你对该路径有读写权限；
3. 该路径的用途和配额允许放你的数据、环境或模型。

lyf 只是你的用户名。管理员问“lyf 应使用哪个非 /home 项目目录”，实际是在问：请管理员给你一个专门的、允许你使用的大文件目录。

## 5. “9902 数据站分配给我哪个目录”是什么意思

数据站是一台单独的机器。它可能有多个大容量磁盘，例如 /data/sdd、/data/sdk。这些目录不等于“谁都可以写”。有的目录属于其他项目，有的只读，有的已经接近满载。

所以你需要管理员明确回答：

    我的用户名 lyf 在 9902 数据站上，应该使用哪个完整路径？
    例如：/data/sdk/lyf/
    这个目录的容量配额是多少？22 端口的 A100 节点能否直接读取它？

如果管理员说 A100 节点可以直接读取，那么你可能会在 22 端口上看到一个共享目录，例如 /nfs-data/sdk/lyf/。这和数据站上的 /data/sdk/lyf/ 可能是同一批数据通过网络共享出来的两个访问入口，但不能凭名字猜测，必须以管理员说明为准。

如果管理员说不能直接读取，就采用：

    9902 数据站：保存大文件
    22 A100 节点：运行实验
    实验开始前：把需要的文件传到 A100 节点
    实验结束后：把 checkpoint 和结果传回数据站

## 6. /data、NFS 和“磁盘”只需要这样理解

你现在不需要掌握复杂的磁盘管理。只要区分下面三个词：

- **目录**：你在命令行中看到的路径，例如 /home/lyf、/data/sdk/lyf；
- **磁盘**：真正保存文件的存储设备；
- **NFS**：通过网络访问另一台机器上的存储设备。

一个目录背后可能对应本机磁盘，也可能对应网络共享磁盘。对你来说，最重要的不是判断它属于哪种技术，而是确认三件事：**路径是什么、我能否写入、剩余空间和配额是多少。**

因此，之前提到的“虚拟文件系统”不是你当前必须掌握的概念。后续实验只按管理员给出的项目路径操作即可。

## 7. SSH 命令和常用检查

登录 A100 服务器：

    ssh -p 22 lyf@211.81.55.158

登录数据站：

    ssh -p 9902 lyf@211.81.55.158

登录后先执行这些只读命令：

    hostname   # 当前是哪台机器
    whoami     # 当前登录用户
    pwd        # 当前所在目录
    df -h      # 各目录所在磁盘的剩余空间

退出远程机器：

    exit

查看 GPU 状态：

    nvidia-smi

不要因为某张卡显示利用率低就直接使用它。先确认调度规则，或者向管理员申请资源；不要停止不认识的 GPU 进程。

## 8. 环境和模型放在哪里

在路径确认之后，可以按下面的方式组织：

    管理员分配的项目目录/
    ├── code/       项目代码或 Git 工作树
    ├── envs/       Python 虚拟环境（如果允许放这里）
    ├── models/     模型缓存或权重
    ├── datasets/   数据集软链接或数据索引
    └── runs/       实验日志、checkpoint、结果摘要

实际情况可能不同。比如管理员可能要求模型全部放在数据站、环境使用公共目录、代码放在共享 Git 目录。这个结构是帮助你理解，不是必须照抄的路径。

## 10. 当前行动顺序

1. 先向管理员确认目录、配额和调度器；
2. 得到路径后，只在分配目录中创建项目文件夹；
3. 在 A100 节点做环境检查，不下载大模型；
4. 确认作业提交方式后，再申请一张 GPU 做最小环境验收；
5. 环境验收通过后，才开始 P0/P1 实验；
6. 大模型、数据集和 checkpoint 统一按管理员的存储规则保存。

目前你不需要理解 NFS、虚拟文件系统或复杂磁盘管理。你只需要先拿到一个明确答案：**“我的项目目录是哪一个，哪个目录可以写，实验通过什么命令申请 GPU？”**
