## 2. 你收到的三条 SSH 命令是什么意思

```bash
ssh -p 22 lyf@211.81.55.158
ssh -p 9901 lyf@211.81.55.158
ssh -p 9902 lyf@211.81.55.158
```

`ssh` 是 Secure Shell，用来通过加密连接登录远程 Linux 主机。`-p` 指定端口；`lyf` 是远程用户名；`211.81.55.158` 是服务器 IP。

端口不是 GPU 编号。这里是管理员把不同机器或入口映射到不同 SSH 端口：22 和 9901 是两台 A100 服务器入口，9902 是数据站入口。登录后看到的主机名才是远端机器的身份，例如本次检查中 22 端口显示 `a100-p22`，9902 显示 `9998`。

## 3. SSH 私钥和主机指纹

你本机已经有可用的 SSH 私钥，两个允许检查的入口都认证成功。私钥只留在本机，不能上传到服务器、发给他人或提交 Git；服务器保存的是对应的公钥。

第一次连接时，SSH 还会询问是否信任服务器的 **host key（主机密钥）**。它用于确认以后连接的确实是同一台服务器，和登录用户的私钥不是一回事。看到主机密钥变化警告时不要直接输入 `yes` 或关闭检查，应先询问管理员是否重装过机器、变更过 SSH 配置。

本次探针为了避免把未经管理员确认的主机密钥写入正式配置，使用了临时信任记录；以后正式工作建议让管理员提供 22 和 9902 的指纹，再保存到本机 `known_hosts`。

## 4. A100 节点、数据站和本机的分工

可以先采用这个简单模型：

```text
本机 Windows：编辑代码、查看日志、提交/监控任务
        │ SSH / scp / rsync
        ▼
22 端口 A100 节点：运行环境、模型推理、训练、实验作业
        ▲
        │ 读取数据或写入结果（按管理员指定路径）
        ▼
9902 数据站：保存数据集、模型权重和大文件
```

这只是角色划分，不代表两个节点之间已经有统一共享路径。`/data/sdd`、`/data/sdk` 等挂载名称可能在不同机器上对应不同设备；必须以管理员指定的项目目录为准，不能因为目录看起来“容量大”就直接使用。

## 5. `/home`、`/data` 和路径的基本概念

- `/home/lyf`：用户家目录，适合少量配置、SSH 设置和小文件。管理员已经要求不要在 `/home` 放数据、模型或环境。
- `/data/...`：通常是本地或共享的大容量盘。只有管理员给出项目目录后才能使用。
- `/nfs-data/...`：网络文件系统挂载。多个机器可能共享它，读写速度、配额和可用空间需要单独确认。
- 相对路径和绝对路径不同。`./runs` 取决于当前目录；`/data/...` 从根目录开始，位置固定。

在服务器上先确认当前目录：

```bash
pwd
whoami
hostname
df -h
```

不要用 `rm -rf` 清理别人或不确定归属的目录。删除前先用 `pwd`、`ls -ld` 和管理员确认路径。

## 6. GPU 的基本概念

`nvidia-smi` 是查看 NVIDIA GPU 状态的工具。常见列包括：

- `GPU Memory-Usage`：显存已使用量，不是系统内存；
- `GPU-Util`：最近一段时间的计算利用率，不是“这张卡是否属于你”；
- `Processes`：当前占用 GPU 的进程；
- `MIG`：如果启用，可能把一张物理卡切成多个实例，需按管理员规则使用。

本次 22 端口节点有 8 张 A100 80GB，但多张显存已被占用。不要直接指定 `CUDA_VISIBLE_DEVICES=0` 就启动训练，也不要杀掉不认识的进程。正确做法是先问清楚实验室使用的是 Slurm、PBS、Kubernetes 还是管理员手工分配，然后通过调度器申请 GPU。调度器分配的 GPU 环境变量会告诉作业应该使用哪些卡。

9902 数据站没有可用 NVIDIA 驱动。即使它名字或挂载中出现 GPU 相关目录，也不能把它当作训练节点。

## 9. 终端、后台任务与作业调度

直接在 SSH 窗口运行长训练有两个风险：网络断开可能结束进程，且没有资源申请记录。正式实验应使用实验室的作业调度器；如果管理员明确允许手工运行，再使用 `tmux` 或 `screen` 保持会话。

不要把 `nohup` 当作调度器。提交作业前至少记录：Git commit、配置文件、任务 split、模型 revision、GPU 数、CPU/内存、开始时间和输出目录。

当前项目的 P0/P1 设计建议从单 GPU、低并发、短任务开始，先做环境验收和 B0/B1 诊断，不要一开始申请多卡或启动完整 RSI 外循环。具体见 [服务器实验设计与配置](C:/Users/刘/Desktop/RSI-Towards-LongHorizon/Project/docs/服务器实验设计与配置.md)。
