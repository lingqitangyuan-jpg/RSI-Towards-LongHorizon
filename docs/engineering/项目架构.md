# 项目架构

**当前代码是可审计的 toy MVP 与接口骨架，不是真实 benchmark runner；真实环境应通过 adapter 接入。**

更新日期：2026-10-26

## 当前已经实现

| 模块 | 当前状态 | 不能据此推出什么 |
|---|---|---|
| contracts / benchmark | 任务、观察、动作、审查决定、结果和 manifest 契约 | 不能推出真实环境 schema 已兼容 |
| environment / policies | 确定性 toy 环境、漂移学生、规则 reviewer | 不代表真实模型或真实教师 |
| runner | bare/reviewed episode、公开轨迹和私有审计分流 | 没有真实 AppWorld launcher |
| sft_export | 从 train split 的 student-visible JSONL 生成样本 | 没有执行 SFT、保存或重载 checkpoint |
| harness_zero integration | 检查参考仓库入口是否存在 | 不会启动 Harbor/AppWorld |
| hyperagents integration | append-only artifact lineage archive | 没有候选生成、选择或 RSI 外循环 |
| server/native acceptance | AppWorld 单训练任务原生 CPU 初始化、公开 API、官方评分与重置负例；真实验收通过 | 不是学生 launcher，也未验收不可信代码隔离 |

原生环境准备入口是 `scripts/server/bootstrap_appworld_native.sh`；已安装后只重跑验收使用 `scripts/server/run_appworld_native.sh`，两者都调用 `accept_appworld_native.py`。结果与限制见 [原生验收记录](../environment/records/2026-10-26_AppWorld原生验收.md)。

## 真实实验的数据流

```text
Benchmark task
  -> environment reset/step/verify
  -> public observation
  -> student proposal
  -> private reviewer: PASS or REPLACE
  -> accepted action
  -> student-visible trajectory + private audit
  -> SFT/LoRA
  -> reviewer-free evaluation
```

环境 adapter 必须负责 reset、step、verify、公开观察和私有字段隔离；核心 runner 不应被 AppWorld 特殊逻辑污染。训练导出器只读公开训练 split，不读审查理由、私有 verifier 状态或最终测试信息。

## 参考仓库的采用边界

- Harness-Zero：采用执行前审查、PASS/REPLACE、接受动作与原始提议分离、学生轨迹与私有审计分离的工程思想。
- HyperAgents：采用候选工件的父代、版本和评测关联；暂不假设其程序演化流程已经适合本项目。
- 两者都不直接成为本项目的研究贡献。贡献判断取决于真实失败机制、严格对照和 reviewer-free 内化证据。

## 下一步代码边界

1. 先实现 AppWorld adapter/launcher 和一任务 P0，不重写 toy runner。
2. 把学生、教师、K、h0、任务、预算和模型 revision 全部放入解析配置。
3. 为每次运行写 config_resolved、manifest、公开轨迹、私有审计、verifier 结果和 failure taxonomy。
4. P0/P1 通过后，再实现真实 SFT/LoRA backend；先做保存/重载 smoke。
5. 最后再实现 K 的多轮更新和 A 的候选生成/选择。
