# 评测与数据协议

**所有方法比较都必须在固定任务、可见信息、学生起点和预算下进行，并把 reviewer-free 结果作为内化的必要检查。**

更新日期：2026-10-26

## 1. 条件定义

| 条件 | 定义 | 评测时是否保留 reviewer/K |
|---|---|---|
| B0 | 初始学生 M0 + 固定部署 h0 | 否 |
| B1 | M0 + h0 + 固定 K0/reviewer，只评测 | 是 |
| B2 | B0 可验证轨迹做 SFT/LoRA | 否 |
| B3 | K0 审查后的 accepted 轨迹做 SFT/LoRA | 否 |
| B4 | 同教师无 K 生成通用审查轨迹 → 对齐 B3 训练量训练学生 → M+h0 评测 | 否 |

B1 只回答外部指导是否有用，不是学生性能上界；B3 才是“移除私有 K 后仍保留收益”的核心条件。

## 2. Benchmark 协议

- 训练、开发、最终测试按 scenario/task family/template 分组切分，避免近重复泄漏。
- 先冻结最终 test 清单、哈希和访问规则；多轮选择和调参只看 train/dev。
- 每个任务必须有 reset、公开 observation、合法 action schema 和独立 verifier。
- 依赖深度来自官方 metadata、参考计划或人工审计；模型调用数、token 数和环境动作数另行记录，不能互相替代。
- 初期 3–5 个任务只用于工程诊断和成本估计；不据此宣布显著提升。

## 3. 日志与隐私边界

每个 run 至少保存：

- resolved config、Git commit、参考仓库快照、任务清单和环境版本；
- 原始学生提议、schema 校验结果、reviewer 决定、接受动作和环境 observation；
- student-visible trajectory；
- private audit、reviewer 原因和 verifier 结果；
- run summary、failure taxonomy、步骤、重试、token、成本和 wall time。

学生历史只能包含任务允许公开的信息和实际接受执行的动作。训练导出器只能读取 train split 的 student-visible JSONL；不能读取审查理由、私有 verifier 状态、测试答案或最终 test。

## 4. 失败分类

每次尝试记录一个主要结果；环境初始化失败时不伪造模型成功率。

| 类别 | 含义 |
|---|---|
| success | 独立 verifier 判定任务完成 |
| model_failure | 环境和动作协议可用，学生行为未完成任务 |
| action_schema_failure | 动作格式不符合约定，未被执行 |
| environment_failure | 数据、依赖、容器、初始化或环境服务失败 |
| timeout | 触发预先指定的时间或步骤上限 |
| verifier_failure | 评分器本身失败，不能得到有效评分 |
| unknown | 证据不足，保留原始日志后人工判断 |

保留所有预定任务作为分母；基础设施失败不能静默丢弃，也不能只比较两组顺利运行的交集。首次运行与重试都保留，重试规则在运行前锁定。

部署预检发现权限或缺失数据，只记录在环境验收中，不创建虚构的 episode，也不把它记为学生模型失败。训练任务的 oracle（已知正确解）验收只检查评分链；即使得到 1.0，也不是 B0/B1 或方法效果。

## 5. 成本与公平性

同时报告两种口径：

- **同学习量：** 对齐有效 SFT token、任务覆盖和优化步数，回答数据是否更有价值。
- **同总预算：** 对齐采样、教师、reviewer、搜索、训练和部署开销，回答方法是否更划算。

失败 rollout、被拒候选、K/A 更新和模型加载成本都计入；训练期教师成本与 reviewer-free 部署成本分开。

## 6. 实验记录

每个真实运行填写 [实验记录模板](实验记录模板.csv)，并在 run 目录保存原始材料。toy demo 只能验证接口与日志分流，不填写为 benchmark 结果。
