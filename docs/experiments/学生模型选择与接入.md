# 学生模型选择与接入

**首个学生选官方 Qwen/Qwen3.5-9B 的原始 post-trained 权重：先对齐 Harness-Zero 的学生起点，再用自己的数据检验指导与内化。**

更新日期：2026-10-26。安装、下载与真实任务的最终状态以本次验收记录和 [近期实验 TODO](../plans/近期实验TODO.md) 为准，不把配置文件当作已运行证据。

## 1. 为什么这样选

我们需要一个能遵守工具协议、权重可获得、后续可自行 SFT/LoRA、成本允许重复迭代的学生。当前优先解决的是“指导是否有效、是否能内化”，不是寻找全领域最强模型。选型依据按以下顺序排列：接近参考实验、权重和训练可控、适配成本、资源预算。

| 候选 | 依据与优势 | 代价或局限 | 决策 |
|---|---|---|---|
| Qwen3.5-9B | Harness-Zero 明确以它做蒸馏学生；官方 Apache-2.0、公开非 gated 权重；同一模型支持 thinking/non-thinking | 混合注意力架构较新，依赖和训练链必须实测；不能沿用旧版 Qwen 的 chat template | 主学生 |
| Qwen3-8B | 官方公开权重、thinking 开关、标准文本推理入口；作为上一代同量级备选便于排查实现兼容性 | 与 Harness-Zero 不同代；原生上下文与新模型不同，换模型后须独立评测 | 兼容性后备，不因单次失败随意更换 |
| Qwen2.5-Coder 7B 系列 | 编码模型家族；Absolute Zero 使用 Qwen2.5-Coder-7B 等作为可训练起点 | Absolute Zero 的 Base 起点不等于 Instruct；其代码/数学成绩不是 AppWorld 工具交互成绩 | 可留作后续旧架构对照，当前不并行铺开 |
| 更大的开放权重或 GPT/Claude API | 可用于教师/参考改进器；HyperAgents 参考代码有多种 GPT/Claude 路由 | API 模型通常不能由本项目直接更新权重；大模型增加多轮数据收集和训练成本 | 学生先不采用，教师另行决策 |

Harness-Zero 的公开结果表中，Qwen3.5-9B 在 AppWorld 上从其最小 Harness 的 26.8 到蒸馏后的 58.9。这里的价值是提供了“同量级学生可内化”的直接参考，**不能把这些数字当作本项目起点或承诺**：我们的执行框架、任务范围、预算和评分设置尚未与其完整协议对齐。

当前服务器检查发现 22 节点有 A100-SXM4-80GB，存在空闲卡。本次官方权重四个分片共 19,306,310,880 字节，约 19.31 GB。这是文件大小，不是推理峰值显存；后者还包括缓存、激活和运行时，必须实测。单卡推理与 LoRA 长序列训练是两个独立验收项。

## 2. 精确选的是哪一个

| 项目 | 固定值 |
|---|---|
| 模型 ID | Qwen/Qwen3.5-9B |
| revision | c202236235762e1c871ad0ccb60c8ee5ba337b9a |
| 权重性质 | 官方 post-trained 模型；不是 -Base，也不是 Harness-Zero 已蒸馏的 checkpoint |
| tokenizer / chat template | 与权重相同 revision，实际模板 SHA256 写入 model-ready.json |
| 精度 | BF16，暂不量化 |
| 输入模态 | 仅文本；用 Qwen3_5ForCausalLM 加载文本主干 |
| 推理后端 | 独立进程中的 Transformers 5.3.0，复用私有 PyTorch 2.6.0+cu124 |
| 自定义远程代码 | trust_remote_code=False；local_files_only=True |
| 上下文预算 | 本项目先固定 32,768，超过预算停止，不静默丢弃历史 |

官方报告的原生上下文上限不是当前实际验收长度；32K 是工程起点，不能写成已验证超长上下文，也不能只因模型支持大窗口就宣称任务具备长程性。

配置：[qwen35_9b.toml](../../configs/models/qwen35_9b.toml)；文件清单与官方哈希：[qwen35_9b_artifacts.json](../../configs/models/qwen35_9b_artifacts.json)。不要使用会漂移的 main 作为实验记录中的模型版本。

## 3. 工程验收与研究设置分开

| 设置 | 工程 smoke | 正式 B0/B1 起始候选 |
|---|---|---|
| thinking | 关闭，先查动作格式与环境交互 | 开启，与参考仓库高推理努力设置方向一致，但不声称完全相同 |
| 解码 | greedy | temperature=0.6、top_p=0.95、top_k=20，固定 seed |
| 单次生成 | 1024 tokens | 8192 tokens |
| 最大环境动作 | 8 | 64 |
| 用途 | 判定模型→动作→沙箱→API→评分能否跑通 | 冻结协议后开展真实基线 |

正式候选解码值参考官方精确编码任务建议。工程 smoke 的低预算可能限制任务成功，**不得混进正式 B0/B1 的分母、与 thinking 结果拼接或用它证明方法收益**。P0 通过后再决定是否调整正式预算，所有条件必须同步改变并记录。

## 4. 接入方式与边界

AppWorld 控制器保留现有 Python 环境；模型在另一个推理 venv/进程中使用指定 GPU，两者通过 JSON 管道通信。模型只接收任务说明和公开观察，生成一个最终 Python 代码块。控制器解析代码，把它交给现有 Bubblewrap adapter；绝不在模型进程或宿主直接执行这段代码。

核心 runner 在执行后调用可选 observe_accepted(action, observation_after)。学生下次只能看到实际被接受的动作及其公开结果；如果 reviewer 将原提议替换，原提议和私有理由不会进入下轮学生上下文。格式错误和不完整 thinking 记作学生失败，不伪装成环境故障，也不执行推理过程里尚未提交的代码块。

独立评分器仍在执行端停止后评分。任务提交标志不等于评分通过。每次记录配置、commit、模型/template revision、输入输出 token、耗时、峰值显存、公开轨迹和私有审计；不加载官方正确解，不访问 test。

## 5. 数据与离线准备

服务器目前无法直连 Hugging Face/ModelScope，故从本地 E 盘准备再传入服务器个人目录。模型分片用官方 SHA256 核对，小文件用官方 Git blob 校验；依赖轮子清单也保存 SHA256。缓存与模型不写入 C 盘或服务器 /home，不更改公共 Conda 和系统驱动。

代码入口依次为 prepare_student.py → install_student_environment.py → model_worker.py → run_student_episode.py。完整职责与伪代码见 [项目代码说明](../engineering/项目代码说明.md)。

## 6. 来源和判断边界

1. [Harness-Zero 官方仓库](https://github.com/metaevo-ai/harness-zero)：学生 ID、AppWorld 表格、LoRA 与高推理努力示例；本地对应快照见 sources/repo/Harness_zero/harness-zero-main/README.md。
2. [Qwen3.5-9B 固定版本模型卡](https://huggingface.co/Qwen/Qwen3.5-9B/blob/c202236235762e1c871ad0ccb60c8ee5ba337b9a/README.md)：许可、post-trained 属性、架构、上下文和解码建议。
3. [Transformers 5.3.0 官方实现](https://github.com/huggingface/transformers/tree/v5.3.0/src/transformers/models/qwen3_5)：固定加载类与依赖版本；5.3.0 并非当前最新版，是本项目选定的可测试版本。
4. [Qwen3-8B 官方模型卡](https://huggingface.co/Qwen/Qwen3-8B)：后备模型特征。
5. [Absolute Zero 官方仓库](https://github.com/LeapLabTHU/Absolute-Zero-Reasoner)：Qwen2.5-Coder 家族作为可训练模型的参考；任务分布不同，不移植其分数。
6. [HyperAgents 代码分析](../analysis/HyperAgents_代码架构与实验工作流分析.md)：它主要启发元层流程，不作为 9B 学生硬件配置的依据。

因此，“适合先验证 IDEA”是工程与实验设计判断，不是已证明该模型能在本项目获得改进。模型实际失败后先区分协议、预算、环境、推理与训练问题，不能直接归因于模型太弱。
