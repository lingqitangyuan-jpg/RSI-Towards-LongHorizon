# 簇二：长程规划、搜索与技能积累

**长程方法通过搜索、重规划、经验或上下文压缩延缓错误累积，但推理时的脚手架收益不等于模型获得了同样能力。**

这一簇的共同判断是：长程失败往往在中间步骤发生，而最终奖励来得太晚。方法因此把搜索、重规划、经验抽取或上下文压缩放到推理时。它们大多提高“当前运行”的成功率，和“把能力内化后撤掉 Harness（执行框架）”之间还有一段距离。

## Tree of Thoughts（ToT）

**Tree of Thoughts（ToT）把线性思维链扩展为可回溯的候选树，缓解一次错误决定锁死后续搜索的问题，但它本身不执行外部动作。**

### 🧩问题背景

CoT 一旦选择错误的中间结论，后面只能沿同一条链继续。失败发生在“没有保留多个候选状态，也没有回溯”。

### ⚙️核心方法

把问题拆成若干 thought 单元，生成多个候选、调用 value 评估器筛选，并用 BFS/DFS 等策略继续扩展或回退。搜索树存的是语言模型生成的思路，不是环境中的真实状态。

### 📊实验结果

| 评测 | 论文报告的结果 | 解读 |
|---|---|---|
| Game of 24、创意写作、交叉字谜 | ToT 在需要回溯的任务上超过 CoT 和自洽采样 | 结果支持树搜索对组合推理有用 |
| 长程工具任务 | 论文未报告与真实环境交互的统一结果 | ToT 的候选思路不能直接替代动作搜索 |

### 🔗谱系位置

ToT 是 LATS 的“搜索思路”前身；LATS 将搜索节点和环境执行结合起来。当前 IDEA 更接近 LATS 的可执行路径，而不是 ToT 的纯文本树。

### ⚠️局限

1. 每个候选都要调用模型和评估器，成本随分支数快速增加。
2. value 评估器的偏差会把搜索引向错误分支。
3. 论文未说明搜索树中哪些思路能被后续模型参数吸收。

**来源：** Yao et al., *Tree of Thoughts: Deliberate Problem Solving with Large Language Models*, NeurIPS 2023, arXiv:2305.10601。

## Language Agent Tree Search（LATS）

**Language Agent Tree Search（LATS）把树搜索放到真实动作和环境反馈上，使 Agent 能在多条交互路径之间回溯，但它的收益仍主要依赖推理时搜索预算。**

### 🧩问题背景

ReAct 只沿一条路径执行，早期错误会带来不可逆的后果；ToT 又没有执行真实动作。缺口是“候选路径的评估与环境状态没有接起来”。

### ⚙️核心方法

以 Monte Carlo Tree Search（MCTS）维护交互树；节点包含环境状态和轨迹，扩展时生成动作，执行后得到观察，回传环境奖励或语言模型反思。搜索、反思和工具执行由 Agent Harness 统一调度。

### 📊实验结果

| 评测 | 论文报告的结果 | 解读 |
|---|---|---|
| HotPotQA、HumanEval、WebShop | GPT-3.5 HotPotQA EM：LATS(CoT+ReAct) 0.71 vs ReAct 0.32；GPT-4 HumanEval pass@1：92.7% vs base 80.1%；WebShop score/success：75.9/38.0% | 同一方法覆盖文本、代码和网页交互，但每类任务的搜索预算不同 |
| Game of 24 | LATS(CoT) success 44%，RAP 40%，ToT 20% | 搜索收益与额外 rollout 预算绑定 |
| 失败轨迹利用 | 节点回溯和反思能把失败状态用于下一次搜索 | 这是一次运行内的复用，不是跨运行的参数更新 |

### 🔗谱系位置

LATS 是“搜索与执行”路线的代表，可作为当前项目的强 Harness baseline。若 K 只是在推理时替换动作，必须和同预算 LATS 比较，避免把搜索预算差异误判为内化收益。

### ⚠️局限

1. MCTS 的扩展和回传会显著增加模型调用次数，长任务预算难以固定。
2. 论文未证明搜索过程中学到的恢复策略在撤掉树搜索后仍保留。
3. 环境奖励可用性决定效果，低反馈或难重置环境不一定适合。

**来源：** Zhou et al., *Language Agent Tree Search Unifies Reasoning, Acting, and Planning in Language Models*, 2023, arXiv:2310.04406。

## Voyager

**Voyager 用自动课程、技能库和执行调试在 Minecraft 中积累可复用技能，展示了长任务技能的外部增长，但技能主要以代码和记忆形式留在 Harness 外部。**

### 🧩问题背景

开放世界任务没有固定题目顺序，Agent 需要把成功动作变成以后可调用的技能；一次性提示无法覆盖不断变化的目标。失败发生在“没有课程和可复用技能资产”。

### ⚙️核心方法

由自动课程生成器提出下一目标，技能库检索相关代码，GPT-4 生成动作并执行；失败时根据环境报错进行迭代调试，成功后把代码加入技能库。

### 📊实验结果

| 评测 | 论文报告的结果 | 解读 |
|---|---|---|
| Minecraft 技能/技术树 | 160 次迭代发现 63 个独特物品，约为基线 3.3 倍；解锁 wooden/stone/iron/diamond 技术层比先前方法快 15.3/8.5/6.4 倍 | 论文将收益归因于课程、技能库和自动调试的组合 |
| 未见任务 | 新世界四类目标中 Voyager 4/4 任务达到 3/3 成功，其他对照为 0/3 | 技能复用发生在外部代码库，论文未报告权重更新或移除技能库后的同等能力 |

### 🔗谱系位置

Voyager 是“技能资产进入外部库”的代表；它与当前 IDEA 的差别正好构成对照：我们的目标是判断 Harness 诱导的行为是否能进入模型权重，而不是一直携带技能库。

### ⚠️局限

1. Minecraft 的 API 和反馈比现实长程任务更规则，迁移到通用应用环境仍不清楚。
2. 自动课程本身提供了很强的搜索先验，难以把技能学习与任务生成收益分开。
3. 论文未报告技能代码被学生模型独立重现时的成功率。

**来源：** Wang et al., *Voyager: An Open-Ended Embodied Agent with Large Language Models*, NeurIPS 2023, arXiv:2305.16291。

## ExpeL

**ExpeL 把成功和失败轨迹提炼成跨任务的自然语言经验，再在新任务中检索经验和示例；它回答“怎样复用经验”，但没有证明经验抽取器本身递归变强。**

### 🧩问题背景

单次试错的结果常被丢弃，下一任务又从零开始。失败发生在“轨迹没有被压缩成可迁移原则”。

### ⚙️核心方法

在训练任务上反复尝试，把成功/失败轨迹放入经验池；对比轨迹并由语言模型抽取自然语言 insight；新任务执行时检索相似成功轨迹和经验，作为提示上下文。

### 📊实验结果

| 评测 | 论文报告的结果 | 解读 |
|---|---|---|
| HotPotQA、ALFWorld、WebShop | 四折均值：HotPotQA 约 39% vs ReAct 28%；ALFWorld 59% vs ReAct 40%；WebShop reward 0.701，success 约 38% | 经验提示提高了下一次运行的任务成功率 |
| 跨任务迁移 | HotPotQA→FEVER：ExpeL 70±0.7%，ReAct 63±0.4% | 迁移结果支持经验的部分跨任务复用，但仍是外部文本记忆 |
| 迁移与训练 | 经验库不需要更新基础模型权重 | 论文未报告抽取器经过多代演化后是否更会选择经验 |

### 🔗谱系位置

ExpeL 是当前 IDEA 的“经验层”近邻；与 Harness-Zero 相比，它保存的是轨迹洞察而非私有 Harness 诱导的可执行动作。可用作“经验提示”对照组。

### ⚠️局限

1. 经验抽取由同类语言模型完成，错误归因会进入经验库。
2. 检索到的经验会增加上下文长度，和长程状态管理发生竞争。
3. 论文未报告移除经验库后模型是否保留经验，无法支持能力内化结论。

**来源：** Zhao et al., *ExpeL: LLM Agents Are Experiential Learners*, 2023, arXiv:2308.10144。

## Plan-and-Act

**Plan-and-Act 将长任务拆成“先形成计划、再执行并按反馈重规划”，减少局部动作把全局目标挤出上下文，但它把计划保留在 Harness 层。**

### 🧩问题背景

纯 ReAct 每一步都重新决定，容易忘记远期子目标；一次性长计划又无法适应环境变化。失败发生在“全局计划和局部反馈没有协调”。

### ⚙️核心方法

先生成可分解计划，执行当前子目标；遇到异常、状态变化或子目标完成时重新规划。计划器和执行器通过共享状态通信。

### 📊实验结果

| 评测 | 论文报告的结果 | 解读 |
|---|---|---|
| WebArena-Lite、WebVoyager | WebArena-Lite success **57.58%**，WebVoyager text-only success **81.36%** | 结果支持显式计划有助于持续目标维护 |
| 参数内化 | 论文未报告把计划能力训练进模型、再撤去计划器的结果 | 不能直接作为当前 IDEA 的内化证据 |

### 🔗谱系位置

它位于 ReAct 与长程 Harness 设计之间，和当前 IDEA 的区别是：Plan-and-Act 关注运行时控制，当前 IDEA 关注运行时辅助能否变成下一代模型能力。

### ⚠️局限

1. 论文不同版本/实现的任务、计划长度和重规划触发条件可能不同，复现时必须锁定版本。
2. 计划错误会在多个子目标中传播，重规划成本也会随任务增长。
3. 论文的 WebArena-Lite 测试集为 165 个任务；方法主要依赖已有成功轨迹和合成计划数据，跨域效果未报告。

**来源：** Erdogan et al., *Plan-and-Act: Improving Planning of Agents for Long-Horizon Tasks*, ICML 2025, arXiv:2503.09572。

## Context-Folding

**Context-Folding 通过把已完成的子轨迹折叠成更短的状态摘要，降低长任务的上下文压力，但压缩错误会把不可见的状态丢失带入后续决策。**

### 🧩问题背景

长程 Agent 的上下文会同时包含历史动作、工具返回和中间思考；直接截断会丢约束，完整保留又超出窗口。失败发生在“上下文增长和关键状态保留无法同时满足”。

### ⚙️核心方法

Agent 主动分支到子轨迹解决局部任务，完成后将子轨迹折叠为结构化摘要，再合并回主轨迹。折叠操作由 Harness 管理，模型继续在压缩后的上下文中行动。

### 📊实验结果

| 评测 | 论文报告的结果 | 解读 |
|---|---|---|
| BrowseComp-Plus、SWE-Bench Verified | Seed-OSS-36B + FoldGRPO 的 pass@1 为 **62.0%/58.0%**；活动上下文约小 **10 倍**，并超过摘要式压缩对照 | 需要同时看压缩率和成功率，单看 token 节省不能证明推理更强 |
| 跨任务内化 | 论文未报告折叠策略进入模型权重后撤去折叠器的结果 | 目前属于 Harness 侧上下文管理 |

### 🔗谱系位置

Context-Folding 和 MemGPT/MEM1 共同处理上下文预算；它为当前项目提供一个可测量的 Harness 变量：同样的学生模型，比较不同状态压缩策略产生的数据是否更可学习。

### ⚠️局限

1. 摘要质量决定后续能否恢复隐含约束，错误摘要不一定能被发现。
2. 子任务边界由系统决定，边界错误会把跨子任务依赖一起折叠掉。
3. 原文使用最多 10 个 branch 和 32K active budget；branch 总处理 token 可以超过 100K，压缩并不等于总计算量降低。

**来源：** Sun et al., *Scaling Long-Horizon LLM Agent via Context-Folding*, 2025, arXiv:2510.11967。

## MEM1

**MEM1 通过每轮生成新的精炼思考并丢弃旧上下文，把长对话压缩成固定大小的状态；压缩稳定性是它的核心风险。**

### 🧩问题背景

长对话中的搜索结果、思考和历史动作会不断占用上下文；完整保留会增加成本，简单截断会丢失目标和事实。

### ⚙️核心方法

每轮把当前对话中重要信息、已经尝试的方法和下一步计划压缩成新的 memory state，再以该状态继续思考；论文将其与强化学习训练结合，让压缩后的状态支持后续决策。

### 📊实验结果

| 评测 | 论文报告的结果 | 解读 |
|---|---|---|
| 16-objective multi-hop QA | MEM1-7B 相比 Qwen2.5-14B-Instruct，性能约 **3.5 倍**、峰值内存约降 **3.7 倍**，并泛化到更长 horizon | 结果同时涉及模型训练与上下文控制，需单独报告两者贡献 |
| WebShop、Wiki-RAG、Online Web-QA | WebShop reward 70.87 vs AgentLM-13B 70.80，peak token 0.81k vs 2.36k；Wiki-RAG 上 MEM1 EM/F1 为 .405/.471 | 论文未报告任意环境下的状态恢复率或失败记忆污染率 |

### 🔗谱系位置

MEM1 属于“把长期状态写成短状态”的路线，与当前 IDEA 的连接是：它可以成为固定 h0 的上下文管理组件，也可以提供一个检查点级别的可内化行为。

### ⚠️局限

1. 每轮压缩都会丢失细节，错误会被写入下一轮的唯一状态。
2. 强化学习成本和训练数据依赖较高，论文未报告在真实工具环境中统一复现的资源需求。
3. 作者报告过 reward hacking：格式奖励使 2-objective EM 从 .709 降至 .466；SFT 在超过 6 个 objectives 时崩溃，说明训练稳定性仍是问题。

**来源：** Zhou et al., *MEM1: Learning to Synergize Memory and Reasoning for Efficient Long-Horizon Agents*, 2025, arXiv:2506.15841。
