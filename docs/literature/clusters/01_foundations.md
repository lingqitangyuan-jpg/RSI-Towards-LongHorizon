# 簇一：基础交互、工具使用与记忆

**基础 Agent 方法先解决“如何行动和记住”，但它们通常只改变推理时系统，尚未回答能力是否进入模型。**

这一簇回答一个前置问题：模型只会生成文本，怎样在有状态环境里持续行动？这些工作主要改变推理时的交互协议、工具接口或记忆层，通常不更新模型权重。因此，它们能让一次运行更强，却不能直接说明能力已经内化。

## Chain-of-Thought（CoT）

**Chain-of-Thought（CoT）把中间推理步骤显式化，使模型能在输出答案前展开多步计算，但它解决的是单次推理链，不是带环境反馈的长程控制。**

### 🧩问题背景

标准 few-shot prompting 只给出输入和答案，复杂算术、符号推理中的中间错误无法被模型自己暴露。失败发生在“从问题直接跳到答案”的推理过程，而不是工具调用或环境状态管理。

### ⚙️核心方法

在示例中加入自然语言推理链，提示模型先生成中间步骤，再输出最终答案。核心选择是把隐含计算变成可继续生成、可检查的文本轨迹；它不提供外部状态存储，也不负责执行动作。

### 📊实验结果

| 评测 | 论文报告的结果 | 解读 |
|---|---|---|
| GSM8K、数学文字题、符号推理 | PaLM-540B 在 GSM8K 上为 **56.9%**，standard prompting 为 17.9%；外接计算器为 58.6% | 结果说明显式中间步骤有助于复杂推理，但没有给出长程环境中的跨步骤成功率 |
| 其他推理集 | PaLM-540B CoT：SVAMP 79.0%、ASDiv 73.9%、AQuA 35.8%、MAWPS 93.3% | 收益依赖模型规模、示例选择和任务格式 |
| 过程可验证性 | 推理链可被人工或程序检查 | 可检查不等于正确，论文未报告将错误链自动修复后再执行的闭环 |

### 🔗谱系位置

CoT 是 ReAct、Tree of Thoughts（ToT）等方法的推理表示基础；与当前 IDEA 的关系是提供“学生可见轨迹”的语言载体，而不是 Harness（执行框架）或 RSI 机制。

### ⚠️局限

1. 推理链可能是事后解释，论文没有证明每一步都对应模型真实的因果计算。
2. 轨迹长度增加会加剧上下文和错误累积；论文未报告跨多轮工具交互的状态保持能力。
3. 需要人工构造带推理链的示例，数据成本和示例质量会影响结果。

**来源：** Wei et al., *Chain-of-Thought Prompting Elicits Reasoning in Large Language Models*, 2022, arXiv:2201.11903。

## ReAct

**ReAct 把推理和行动交错起来，让模型在环境反馈后再决定下一步，但它的单路径执行仍会把早期错误带入后续步骤。**

### 🧩问题背景

CoT 只在文本中推理，无法查询外部信息或改变环境；纯行动策略又缺少对当前目标和错误原因的显式解释。失败点是“推理与行动脱节”。

### ⚙️核心方法

采用 `Thought → Action → Observation` 循环：模型写出当前判断，调用搜索或环境工具，读取观察，再继续生成。Harness（执行框架）负责把动作发送给工具并把观察拼回上下文。

### 📊实验结果

| 评测 | 论文报告的结果 | 解读 |
|---|---|---|
| HotpotQA、FEVER | PaLM-540B 的 ReAct：HotPotQA EM 27.4%，FEVER 60.9%；ReAct→CoT-SC 分别为 35.1% 和 64.6% | 证据回填减少了纯记忆回答，但任务主要按最终答案计分 |
| ALFWorld、WebShop | ALFWorld 平均完成率 57%，best-of-6 为 71%；WebShop score/success 为 66.6/40.0% | 这是单次运行或有限重试的即时收益，论文未报告模型权重更新后的能力保留 |

### 🔗谱系位置

ReAct 是 LATS、Voyager、Reflexion 等工作的执行骨架。当前 IDEA 可以把 ReAct 视为固定 h0 的动作接口，但私有 K 的审查仍需额外设计。

### ⚠️局限

1. 失败动作已经执行后才产生观察，错误可能继续污染后续状态。
2. 论文未把“首次偏离目标的步骤”作为独立诊断指标，长任务中的信用分配仍然粗糙。
3. 推理文本、工具调用和环境状态全部进入上下文，长轨迹会遇到上下文窗口与成本约束。

**来源：** Yao et al., *ReAct: Synergizing Reasoning and Acting in Language Models*, ICLR 2023, arXiv:2210.03629。

## Reflexion

**Reflexion 将失败后的语言反馈和自我反思写入外部记忆，使下一次尝试能避开已知错误，但改进主要发生在推理时而非模型权重中。**

### 🧩问题背景

ReAct 的一次轨迹失败后，下一次运行通常重新开始；模型没有稳定的失败经验。问题发生在“反馈没有跨试次保留”。

### ⚙️核心方法

任务完成或失败后生成 verbal feedback，把它写入 episodic memory；下一次执行时检索相关反思。系统还可以使用外部评估器提供稀疏奖励，决定何时生成反思。

### 📊实验结果

| 评测 | 论文报告的结果 | 解读 |
|---|---|---|
| HumanEval、HotpotQA、ALFWorld | ALFWorld 完成 130/134；HumanEval Python pass@1 为 91.0%（对照 GPT-4 为 80.1%）；HotPotQA 在 CoT(GT) 上增加 14 个百分点 | 结果支持“语言反馈可复用”，但每个基准使用不同反馈和记忆设置 |
| 反思消融 | 去掉语言反馈或记忆后性能下降 | 说明记忆层是收益来源之一，不能归因于模型能力本身 |

### 🔗谱系位置

它把 ReAct 的单次循环扩展为多次尝试，是 ExpeL 和 RSIAgent 等经验积累方法的前驱。与当前 IDEA 的差别在于，Reflexion 保存的是经验文本；我们的目标是把 Harness 诱导行为写入权重并移除私有审查。

### ⚠️局限

1. 反思质量依赖语言模型和外部奖励，错误的反思会被重复检索。
2. 论文未报告反思机制本身经过多代修改后是否更会生成有效反思，因此不足以证明狭义 RSI。
3. 记忆库会增长，长期任务下的检索冲突、污染和成本没有统一解决。

**来源：** Shinn et al., *Reflexion: Language Agents with Verbal Reinforcement Learning*, NeurIPS 2023, arXiv:2303.11366。

## MemGPT

**MemGPT 把有限上下文当作层级内存管理问题，让 Agent 主动搬运和压缩信息；它缓解上下文瓶颈，却没有改变基础模型的推理能力。**

### 🧩问题背景

长对话或长任务会超出模型上下文窗口；简单截断会丢掉早期目标和事实。失败发生在“所有历史都塞进同一个上下文”。

### ⚙️核心方法

仿照操作系统的虚拟内存，把核心上下文、外部 archival memory 和检索/写入函数分层。模型决定何时把信息写入外部存储、何时召回，并通过函数调用维持会话状态。

### 📊实验结果

| 评测 | 论文报告的结果 | 解读 |
|---|---|---|
| 多会话深记忆检索（DMR） | GPT-4：32.1/.296 → MemGPT 92.5/.814（accuracy/ROUGE-L）；GPT-4 Turbo：35.3/.359 → 93.4/.827 | 证明分层 memory 有效，但结果依赖检索调用是否正确 |
| Nested KV 与长对话 | MemGPT+GPT-4 在增加嵌套层数时保持较稳定；普通基线在较浅层级即降为 0% | 论文未报告把记忆策略蒸馏进模型权重后的独立泛化 |

### 🔗谱系位置

MemGPT 属于 Harness 侧上下文管理；Context-Folding、MEM1 可以看作进一步的压缩/状态化路线。当前 IDEA 应把它作为 h0 的基础能力，而不是把记忆增长误判为 RSI。

### ⚠️局限

1. 写入和召回由同一个模型决定，错误记忆可能长期保留。
2. 论文未提供统一的长程工具任务协议来区分“记住了”与“正确执行了”。
3. 额外检索和存储调用增加延迟，成本随会话长度和记忆规模增长。

**来源：** Packer et al., *MemGPT: Towards LLMs as Operating Systems*, 2023, arXiv:2310.08560。

## Toolformer

**Toolformer 让模型从少量示例中学会在合适位置调用工具，解决的是“何时调用工具”，不是多步任务中的全局计划。**

### 🧩问题背景

语言模型在算术、检索和时间查询上可能有知识或计算错误，但人工为每个任务写工具调用规则成本高。失败发生在“模型不知道何时把问题交给外部工具”。

### ⚙️核心方法

先用少量人工标注的 API 示例生成候选调用，再用 API 返回结果和语言模型损失筛选有用调用，把调用结果拼回预训练数据，进行自监督训练。

### 📊实验结果

| 评测 | 论文报告的结果 | 解读 |
|---|---|---|
| 计算器、搜索、日历、翻译等 API | GPT-J 在 LAMA 的 SQuAD/Google-RE/T-REx 为 33.8/11.5/53.5，原 GPT-J 为 17.8/4.9/31.9；算术 ASDiv/SVAMP/MAWPS 为 40.4/29.4/44.0 | 工具调用被写入参数，属于能力学习的一种早期形式 |
| 长程交互 | 论文未报告统一的长程 Agent 环境成功率 | 不能把单次 API 调用收益外推成多步 Harness 内化 |

### 🔗谱系位置

Toolformer连接了参数化模型与工具，后来许多 Agent 把它改成 ReAct 式推理时调用。当前 IDEA 的“用 h0 执行动作”可以借鉴其工具接口，但 K 的审查仍要处理跨步依赖。

### ⚠️局限

1. 候选 API 调用和筛选成本较高，规模化到复杂工具链并不直接。
2. 论文主要报告单次调用或短链任务，未说明错误调用如何在长轨迹中恢复。
3. 工具返回的外部知识可能被模型记住，但不等于模型掌握了可迁移的任务策略。

**来源：** Schick et al., *Toolformer: Language Models Can Teach Themselves to Use Tools*, NeurIPS 2023, arXiv:2302.04761。
