# 簇四：RSI、自我改进与能力内化

**RSI 研究的分水岭不是系统会不会改代码，而是改进结果能否被继承，并让下一轮改进器变得更有效。**

这一簇最接近当前研究方向，但“系统分数上涨”“代码被修改”“改进器本身变强”必须分开。下面沿用 Note.md 的三层判断：广义自我改进、结构性 RSI、狭义 RSI。标签是本项目的操作性分类，不是全领域统一标准。这里的 Harness（执行框架）包括提示、工具编排、记忆、控制流和评估钩子。

| 工作 | 主要更新对象 | 广义自我改进 | 结构性 RSI | 狭义 RSI 判断 |
|---|---|---|---|---|
| RSIAgent | 外部记忆 | 是 | 记忆被复用 | 未证明改进器更强 |
| DGM | Agent 代码与档案 | 是 | 实际多代代码回返 | 任务曲线不能单独证明 |
| HyperAgents | Agent 与 meta-agent 代码 | 是 | meta 层也可回返 | 有跨域后续改进证据，但未完全隔离因果 |
| ADAS | 候选 Agent 代码 | 是（系统边界） | 候选搜索回返 | meta-agent 固定，未证明 |
| SICA | coding Agent 代码 | 是 | 实际多轮自修改 | 未证明跨域改进器收益 |
| Dream-RSI | 探索调度策略 | 是 | 历史树回放→在线策略回返 | 论文报告效率提升，尚非严格旧/新改进器交换 |
| Harness-Zero | 学生模型权重 | 是（含外部教师边界） | 单向内化，不是完整递归回返 | 未证明 |

## RSIAgent

**RSIAgent 把多角色探索经验写入记忆模块，展示了无需微调的 Agent 自我演化，但现有实验没有证明“探索能力本身”随轮次变强。**

### 🧩问题背景

不同环境中的成功经验通常只停留在当前会话；重新遇到相似任务时，Agent 需要重复探索。失败发生在“经验没有被组织成后续可调用的记忆”。

### ⚙️核心方法

使用多个角色进行探索、总结和评审，把经验存入 memory module；后续任务检索相关经验，不修改基础模型权重，也不要求模型自动重写 Harness（执行框架）代码。

### 📊实验结果

| 评测 | 论文报告的结果 | 解读 |
|---|---|---|
| OSWorld-v2、Agent's Last Exam | OSWorld partial/binary：71.97/37.80 → **78.98/42.68**；ALE：83.75/49.25 → **84.82/50.75** | 这证明记忆能帮助当前系统，但实验没有报告跨新环境的探索效率曲线 |
| 权重更新/改进器迁移 | 论文未报告 | 不能仅因论文标题带 RSI 就判定狭义 RSI |

### 🔗谱系位置

它位于 Reflexion/ExpeL 的经验记忆路线，与 DGM/HyperAgents 的可编辑代码路线不同。当前 IDEA 可以把它作为“只加记忆”的对照，检验 K 的收益是否只是记忆提示带来的。

### ⚠️局限

1. 记忆模块没有统一的错误删除和冲突解决机制。
2. 两个 benchmark 的结果不能说明探索策略在第三个环境中会继续改进。
3. 论文未报告记忆移除后的能力保留，也未比较改进器在后续代际的收益。

**来源：** Zhu et al., *RSIAgent: Autonomous Exploration for Recursive Self-improvement in New Environments*, 2026, arXiv:2609.15364。

## Darwin Gödel Machine（DGM）

**Darwin Gödel Machine（DGM）通过评测自修改代码并把高分变体放入档案库，展示了编码领域的开放式自我改进，但它的元层机制仍由人工固定。**

### 🧩问题背景

传统 Agent 改进过程依赖固定提示、固定搜索策略或人工选择；一旦初始改进规则到达瓶颈，系统无法自己改变“如何改自己”。

### ⚙️核心方法

维护一个 agent archive，从已有 Agent 采样；Meta-Agent 根据评测反馈生成代码修改，运行新版本，通过基准测试后把高分版本加入档案，继续作为后代的父代。DGM 的父代选择和修改指令生成机制仍是预先写好的。

### 📊实验结果

| 评测 | 论文报告的结果 | 解读 |
|---|---|---|
| SWE-bench、Polyglot | 80 轮后 SWE-bench Verified **20.0%→50.0%**，Polyglot **14.2%→30.7%**；作者还报告跨 benchmark transfer | 这支持结构性 RSI，但主要集中在 coding 任务 |
| 改进器收益 | 论文把任务表现提升作为自我改进证据，未完全隔离“旧 Meta-Agent 与新 Meta-Agent”在相同预算下的产出效率 | 不能只凭曲线证明狭义 RSI |

### 🔗谱系位置

DGM 是 HyperAgents、ADAS、SICA 等代码级自修改工作的直接前驱。当前 IDEA 借用其档案/选择压力，但把变体从完整 Agent 代码换成私有 K，并增加权重内化与固定 h0 部署。

### ⚠️局限

1. coding 任务同时是被评测任务和自修改任务，任务能力与自改能力高度对齐。
2. 评测预算、父代选择和测试集使用方式会直接影响档案增长。
3. 论文未解决私有 Harness 的能力如何进入模型权重并在部署时独立工作。

**来源：** Zhang et al., *Darwin Gödel Machine: Open-Ended Evolution of Self-Improving Agents*, 2025, arXiv:2505.22954。

## HyperAgents

**HyperAgents 把任务代理和元代理放进同一个可编辑程序，使“产生下一代的方法”也能被修改；它提供了目前最接近狭义 RSI 的跨域证据，但迁移时同时改变任务代理和元代理。**

### 🧩问题背景

DGM 的任务和自修改都是 coding，任务成绩上升可能只是领域对齐；在论文审稿、机器人奖励设计或数学评分等领域，固定元层可能不知道怎样提出有效修改。

### ⚙️核心方法

Hyperagent 同时包含 task agent 与 meta agent；meta agent 可以修改自身、任务代理、记忆和评测辅助代码。系统保留 archive 和 open-ended branching，允许后代继续改写产生后代的程序。

### 📊实验结果

| 评测 | 论文报告的结果 | 解读 |
|---|---|---|
| Polyglot coding | DGM-H 的改进幅度与 DGM 相当 | 说明可编辑元层没有让编码任务退化 |
| 论文审稿、机器人奖励设计 | 论文审稿 0→0.710，机器人奖励设计 0.060→0.372；论文审稿静态基线为 .630、DGM-custom 为 .590，机器人任务未报告可直接对齐的静态基线 | 支持跨任务迁移，但每个领域的外部评测器不同 |
| 跨域迁移 | 从论文审稿/机器人设置迁移的是整个 hyperagent（task + meta），在 IMO grading/proof、search-arena 上继续产生改进 | 这是比单纯任务曲线更强的 RSI 证据，但不是只替换 meta agent 的因果实验 |
| 组件消融 | 去掉 self-improvement 或 open-ended exploration 后进步很小或没有 | 支持组件必要性，但不能说明哪一种元改动最有效 |

### 🔗谱系位置

HyperAgents 是本项目元层设计的主要启发：A_t 可以演化 K_t 的结构与审查规则。但它不处理权重内化，也没有固定 h0 下“撤掉训练期 K 后的能力保留”实验。

### ⚠️局限

1. 论文主实验中 parent selection 仍由人工机制固定；完全自指的选择器只在补充实验中被初步探讨。
2. 跨域迁移同时带走 task agent 和 meta agent，无法纯粹归因于“改进器变强”。
3. 每个后代都要运行评测和代码修改，成本、沙箱和安全约束会限制长程环境规模。

**来源：** Zhang et al., *HyperAgents*, 2026, arXiv:2603.19461；实验版本以项目本地 `sources/articles/HyperAgents.pdf` 为准。

## ADAS

**ADAS 把 Agent 设计本身变成搜索对象，让元模型生成、评测和保留不同 Agent 程序；它是自动化系统设计路线，不等于模型权重的递归自我改进。**

### 🧩问题背景

手工组合规划器、工具调用、记忆和评估器需要大量工程经验；固定模板也可能在新任务上失效。失败发生在“设计空间太大而人工搜索太慢”。

### ⚙️核心方法

维护候选 Agent 及其评测结果，由 Meta-Agent 编写新的 Agent 代码或提示，运行基准后把表现好的候选纳入 archive。搜索对象可以包含提示、工具编排和控制流。

### 📊实验结果

| 评测 | 论文报告的结果 | 解读 |
|---|---|---|
| DROP、MGSM、MMLU、GPQA | Meta Agent Search 相对手工 SoTA：DROP F1 **+13.6**，MGSM accuracy **+14.4**；MGSM→GSM8K/GSM-Hard 转移为 **+25.9/+13.2** | 证明 Agent 结构可以被搜索 |
| 参数内化/元改进 | 论文未报告将搜索到的结构训练进模型权重，也未报告严格的旧/新 Meta-Agent 配对实验 | 不能直接归入狭义 RSI |

### 🔗谱系位置

ADAS 是 HyperAgents 之前的自动设计路线，可作为当前 A_t 的外部搜索基线。当前 IDEA 的额外约束是：候选 K 必须产生可执行、可学习、能在 h0 下部署的轨迹。

### ⚠️局限

1. benchmark 分数既用于搜索又用于选择候选时，过拟合风险很高。
2. Agent 代码越复杂，解释、复现和安全审查越困难。
3. 论文未报告候选 Harness 的教学价值或移除后的能力保留。

**来源：** Hu et al., *Automated Design of Agentic Systems*, ICLR 2025, arXiv:2408.08435。

## SICA

**SICA 代表“自动改进 coding agent”的路线：系统根据失败反馈修改 Agent 实现并重新评测，但其收益依赖代码任务与代码自修改的领域对齐。**

### 🧩问题背景

coding Agent 的提示、工具编排和错误恢复策略通常由人工维护；模型在不同仓库上遇到的失败模式又不相同。

### ⚙️核心方法

让 Agent 读取自己的实现、失败轨迹和评测信息，提出代码或提示修改，运行测试，保留通过验证的版本。候选以版本或档案形式继承。

### 📊实验结果

| 评测 | 论文报告的结果 | 解读 |
|---|---|---|
| SWE-bench Verified、file-edit、symbol、LiveCodeBench | 16 轮中 SWE-bench Verified **0.17→0.53**；file-edit 峰值 0.96，symbol 峰值 0.43，LiveCodeBench 峰值 0.71 | 结果支持代码级自修改有效 |
| 跨领域内化 | 论文未报告固定 h0、权重更新或跨非代码任务迁移 | 不能把 coding 自修改直接外推到长程应用任务 |

### 🔗谱系位置

SICA 与 DGM 同属代码级结构性 RSI，HyperAgents 再把元层也设为可编辑。当前项目希望把“可修改 Harness”进一步变成“可内化的训练数据”。

### ⚠️局限

1. 代码测试提供了密集、可重置反馈，与 AppWorld/现实工具环境不同。
2. 代码修改可能只优化 benchmark 适配，而不增加可迁移能力。
3. Note.md 未记录版本和精确实验数字；本卡片不编造结果。

**来源：** Robeyns et al., *A Self-Improving Coding Agent*, 2025, arXiv:2504.15228。

## Dream-RSI

**Dream-RSI 把 Agent 上方的调度/元策略作为自我优化对象，重点是冻结历史、快速评测和选择后代，而不是把策略蒸馏进模型权重。**

### 🧩问题背景

多 Agent 或多阶段系统的瓶颈可能不在单个执行 Agent，而在“何时调用哪个 Agent、如何分配预算”的调度策略。

### ⚙️核心方法

保存历史版本形成树状候选，使用快速评测比较元策略，选择更优调度版本继续生成后代。具体候选表示、任务和评测器随论文版本而定。

### 📊实验结果

| 评测 | 论文报告的结果 | 解读 |
|---|---|---|
| 4 个领域、9 个任务 | KernelBench 的若干任务在相同质量下减少 discovery-agent calls 1.79–2.43 倍；其他设置的 discovery efficiency 也有提升 | 说明调度层可以成为搜索对象 |
| 模型权重内化 | 论文未报告 | 它与当前 IDEA 的差异在于是否把调度/审查能力写回学生模型 |

### 🔗谱系位置

Dream-RSI 补充了 DGM/ADAS 的“元策略层”视角；它启发我们把 K 的选择压力从即时外挂分数扩展到内化后表现，但该连接仍需实验验证。

### ⚠️局限

1. 快速评测若与最终任务分布不一致，会选择错误的元策略。
2. 历史树规模增长带来存储和评测成本。
3. Note.md 没有给出足够的原文元数据和数字，本卡片明确标记待补。

**来源：** Zheng et al., *Dream-RSI: Recursive Self-Improvement through Evolving Worlds*, 2026, arXiv:2609.14858。

## Harness-Zero

**Harness-Zero 将优化 Harness 的行为转成目标 Harness 动作空间中的可执行修正，再用这些轨迹训练学生；它是当前 IDEA 的直接能力内化基线，但单轮蒸馏不等于递归 RSI。**

### 🧩问题背景

Agent 性能由模型和 Harness 共同决定；一个领域或实例优化的 Harness 可能很强，却难以在不同任务、模型或部署环境中复用。失败发生在“优化 Harness 的动作空间和目标 Harness 不一致，轨迹不能直接模仿”。

### ⚙️核心方法

用 agent-as-harness 在学生响应执行前审查：保持合理动作，或把动作改写成目标 Harness 可执行的完整响应。修正后的响应通过固定目标 Harness 执行，环境观察回到学生上下文；私有审查讨论不进入学生可见轨迹。用接受轨迹微调学生，部署时移除优化 Harness。

### 📊实验结果

| 评测 | 论文报告的结果 | 解读 |
|---|---|---|
| SpreadsheetBench、AppWorld、USPTO | agent-as-harness 平均表现 81.1%，code-as-harness 78.1%；三类任务分别使用 pass@1 或 scenario goal completion | 说明在同一演化 Harness 下，语言代理审查可比代码 Harness 更强 |
| Distillation | 撤掉专用 Harness 后，蒸馏模型保留了大部分收益；28 个行为模式平均恢复率 82.3% | 这是当前 IDEA 最直接的“外部指导→权重→简化部署”证据 |
| 三域部署总结果 | 基础模型宏平均 success **23.3%→44.3%**；撤掉专用 Harness 后为 44.3%，仍带专用 Harness 的对照为 41.7% | 结果是跨 SpreadsheetBench、AppWorld、USPTO 的汇总，不能解释为每个领域都超过带 Harness 对照 |
| 任务细节 | SpreadsheetBench 300 训练/100 测试；AppWorld 147 训练/168 测试；USPTO 500 训练/100 测试 | 说明作者确实区分了训练和评测任务，但不能替代我们自己的数据边界审计 |

### 🔗谱系位置

Harness-Zero 解决的是“一次把优化 Harness 的行为蒸馏到模型”；HyperAgents 解决“元机制也能被改写”。当前 IDEA 想把两者接成循环：A_t 生成 K_t，K_t 产生可学习轨迹，模型更新后再反馈给 A_t/K_t。

### ⚠️局限

1. 论文的单向蒸馏结果不自动证明多轮更新 K、A 后改进器本身更强。
2. 优化 Harness 的设计、训练轨迹筛选和教师模型能力都会影响恢复率；需要与普通教师、自训练做同预算对照。
3. “部署时移除专用 Harness”仍依赖目标 Harness；这和完全无外部审查器不是同一命题。
4. 领域知识在不同任务上的恢复并不均匀，论文的平均恢复率不能替代检查点级分析。

**来源：** *Harness-Zero: Harness Distillation*, 2026, arXiv:2609.24974；本地全文：`sources/articles/Harness_zero.pdf`。

## 当前项目 IDEA：三个待验证焊接点

**当前 IDEA 的研究价值不在于把两个模块画成闭环，而在于检验“可蒸馏性”能否反过来成为 Harness 演化的选择压力。** 下面是研究假设，不是已有论文结论。

### 🧩问题背景

现有工作分别展示了 Harness 即时辅助、轨迹学习或元机制演化，但较少把“学生最终能否在固定 h0 下独立完成任务”作为 K 的首要选择标准。可能存在一种情况：即时救场最强的 K，产生的轨迹却不容易学习。

### ⚙️核心方法

当前草案包含三个连接点：

1. **可蒸馏性选择压力**：档案 fitness 不只看 K 的即时任务分数，也看撤掉 K 后学生的独立收益。
2. **内化失败作为诊断信号**：频繁 REPLACE 但学生更新后仍失败，反馈给 A，促使 K 改写规则或动作结构。
3. **检查点作为共同语义单元**：A 演化检查点级规则，K 在检查点 PASS/REPLACE，评估时看每类检查点的恢复率。

### 📊实验结果

论文未报告这些焊接点的实验结果；它们必须通过分阶段 pilot 验证。第一步应比较无 K、固定 K 和同预算训练后的无 K 部署，而不是同时演化 M、K、A 和课程。

### 🔗谱系位置

这是 Harness-Zero 的内化路径、HyperAgents 的元层、ExpeL/Reflexion 的经验复用和信用分配工作的交叉假设。它不能因为结构上“拼接得完整”就自动成为新方法。

### ⚠️局限

1. 嵌套训练成本很高，K 的 fitness 可能需要等待学生微调和独立评测后才能计算。
2. 外部教师可能直接接管任务，学生看到的轨迹不一定包含可迁移的决策依据。
3. 检查点设计、替换比例、任务难度和测试划分都可能制造表面上的可蒸馏性收益。
